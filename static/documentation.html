Behind the Scenes of the CampusConnect Engine

How It Works

Welcome to the technical summary of the CampusConnect Recommendation Engine! This document outlines every step taken in the original Jupyter Notebook analysis to transform raw student data into a highly accurate semantic recommendation system.

1. Data Ingestion & Normalization

The raw dataset `final_data.csv` is loaded into a Pandas DataFrame. The primary features include Academic History (`Course`, `Semester`, `CGPA`), Technical Proficiencies (`Skills`, `Interested_domain`), and Extracurricular work (`Projects`, `Number of Projects`).

  • Null Handling: Any missing values under the projects section are replaced with "no projects".
  • Standardization: All textual fields are transformed to strictly lowercase to ensure matching uniformity.
  • Feature Normalization: Because variables like `CGPA` (0-10) and `Number of Projects` exist on vastly different scales, Min-Max Scaling equations are utilized to compress them both individually into a uniform [0.0, 1.0] scale framework.

2. Text Vectorization

Historically, Term Frequency-Inverse Document Frequency (TF-IDF) was tested. However, TF-IDF relies primarily on exact keyword matches, and struggles to comprehend synonyms or abstract phrases.

"Transitioning to advanced NLP..."

We implemented SentenceTransformers (all-MiniLM-L6-v2) to compute high-density embeddings. Every student's combined Skills and Projects text is mapped into a rich 384-dimensional mathematical vector space, encapsulating the true abstract meaning of their technological stack.

3. Unsupervised Clustering (K-Means)

Before peer recommendation, clustering attempts were visualized. By running a standard K-Means across the entire dataset utilizing our newly calculated sentence embeddings, we observed groupings of similar technical domains.

An Elbow Method graph comparing the number of clusters (K) against Model Inertia was plotted to determine the optimal subset size.

4. The Recommendation Formula

At the engine's core is our multi-variable scoring calculation algorithm.

Final Score = (0.80 * Cosine Similarity)
+ (0.12 * Normalized Project Count)
+ (0.08 * Normalized CGPA)

This ensures semantic relevance guarantees 80% weight, while raw academic hustle (Projects) holds 12% sway, and structural grades (CGPA) dictate the final 8%. The system filters, ranks, and returns the highest predictive scores to the user securely on the FastAPI backend.
